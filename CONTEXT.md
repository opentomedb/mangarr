# Mangarr — Context

Mangarr is a **fork of Readarr** turned into a manga *arr that looks, navigates, and operates
exactly like the Servarr family (Sonarr / Radarr / Lidarr / Readarr) — because it *is* that code,
with manga concepts swapped in for ebooks/audiobooks. Guiding principle: **keep everything exact
and byte-compatible with Readarr, then make small additive changes to suit the manga vision.**

## Domain mapping (the one thing to internalize)

| Servarr/Readarr concept | Mangarr meaning |
|---|---|
| **Author** | a manga **Series** (e.g. "One Piece") |
| **Book** | a **Volume** (has `VolumeNumber`; e.g. "One Piece Vol. 114") |
| **Edition** | a thin **file-attach point**; manga = one edition (Archive), light novel = an EPUB edition + an Audio edition (`Edition.MediaType`) |
| `Author.Library` | `manga` \| `lightNovel`, derived from the foreign id (`~ln`). The index shows one library at a time — the Manga \| Light Novels tab row is the route (`/manga`, `/lightnovels`); light-novel pages carry Readarr's toolbar shape with one `Search EPUB` / `Search Audio` button (`AuthorSearch`/`BookSearch` and `GET /release` carry `mediaType`), manga pages keep the fork's buttons |
| `Author.CopyInPending` | true from the add of a light-novel entry until `ImportExistingLightNovels` has run clean for it (migration 050, 2026-09-17); while true no automatic search or RSS grab touches the entry (`ReleaseSearchService`, `BookSearchService`, `CopyInPendingSpecification`); the add queues the copy-in itself (`SearchAfter` carries search-on-add); `UpdateAuthor` never changes it; the LN series page shows it and has an Import Existing button. Never true for manga |
| Wanted presets + scoped searches (UI polish, 2026-09-21) | Missing/Cutoff Unmet filter presets `manga`, `lightNovelEbook`, `lightNovelAudio`, `lightNovelBoth` (API `library`+`mediaType`, HAVING in `BookRepository`); `MissingBookSearchCommand`/`CutoffUnmetBookSearchCommand` carry nullable `MediaType`, `Library` and `BothEditions`, honoured in `BookSearchService.Execute` (a manga-scoped run never builds the audio probe); an LN row search sends its edition's `mediaType`. Search All searches what the page lists |
| Preferred light novel format (settings tidy, 2026-09-23) | Config `PreferredLightNovelFormat` `epub\|azw3\|kepub` (default epub, validated by `PreferredFormats.IsKnownLightNovelFormat`, 400 otherwise; `LightNovelOutputFormat` maps it to calibre's OutputFormat) — a calibre delivery-conversion setting, not a grab order, so it lives in Settings → Media Management → Light novel storage, not a Formats section. ## Metadata providers (layered, all fail-soft)

Discovery happens in `BookInfoProxy.BuildFakeAuthor` (synthesizes a Series + its Volumes locally,
no metadata server). Providers under `src/NzbDrone.Core/MetadataSource/`:

- **AniListService** — covers, synopsis, titles, status, the authoritative FINAL volume count
  (only when a series is FINISHED), and `averageScore` → series/volume rating (score ÷ 20). Since
  2026-09-15 a series is **bound by id** (`AuthorMetadata.AniListId`, migration 049): the catalogue's
  `anilist_id` first, else a ranked strict title match (`AniListRanker` — no one-shots, primary title
  over synonym, volume-count sanity against the catalogue, popularity on a tie, alias retry), never a
  relaxed hit; the series page's **Fix Match** changes it, `ReResolveMetadata rebind:true` re-picks
  the whole library. Since 2026-09-24 the ranker mirrors OpenTome's `resolve_anilist.py` fallback
  tiers (below exact equality, strict, pinned like primary/synonym): R7 `article` (one leading
  the/a/an dropped, never beside an exact primary), R5 `substring` (own name only, no equal title on
  the page, one candidate with the EXACT catalogue count), R4 `ceiling` (own name only, an exact
  title rejected solely by the 4x ceiling); R6 puts the name minus a trailing edition parenthetical
  (`AniListRanker.EditionStripped`) after the de-slugged id in the alias list, ranked like an alias
  and sharing its `MaxAliasSearches`. R4/R5 need a catalogue count AND an entry name that IS the
  hinted line's name (`MangaSeriesMetadataProvider.IsLineName`, keys compared, the light-novel
  qualifier stripped) — `CatalogueHint` also finds a line by alias or subtitle, and then the count
  is not the name's. So an uncatalogued series, or one found by alias/subtitle, only gains R6/R7.
  The de-slugged id is dropped and never searched when it keys like the name (the usual case).
  **Title fold (2026-09-24, OpenTome's `fold()`):** `TitleMatcher.Normalize` (the key) and
  `TitleNormalizer.ForSearch` (the outbound term) both run `TitleFold.Fold` first — an accent on a
  Latin letter is dropped (explicit code-point table in `TitleFold`, full-width excluded), a No/Nl
  numeric symbol becomes its NFKC form and U+2044 "/" ("Ranma ½" is asked as "Ranma 1/2", keys
  ranma12); kana voicing marks, Hangul, CJK, Cyrillic unchanged; the key keeps No/Nl characters
  with no NFKC form (Python's `isalnum`). The alias walk's `seen` also holds the name's
  ASCII-only keys (OpenTome's `alias_terms` seed), so a stored "fushigi y gi" / "ranma" row of the
  name never spends a `MaxAliasSearches` search.
  The relaxed search-box pass is unchanged and runs only after every strict tier.
  **Display fallback (2026-09-24):** OpenTome's `series.display_anilist_id` / `display_anilist_via`
  (`parent` | `medium`; set only where `anilist_id` is null; read as NULL from an artifact without
  the columns — `GcdMetadataService.LoadOptionalColumns` reads them in their own guarded query, like
  medium / parent_series_id / author, so any older artifact still answers) is never a
  binding. When a pass ends with no AniList id at all (no stored id, even one that failed to fetch;
  no catalogue `anilist_id`, even one that failed; nothing pinned by the search) and the hint line
  carries one, `GetById` fetches it (once per `ProviderLookup`, so the search box's 10-minute cache
  covers it) and ONLY its cover becomes the series poster when no tier gave one (`PosterSource`
  `anilist-display`; never a volume row's fallback art, `VolumeCoverUrl` stays null) and ONLY its
  description the overview when none was found; id, titles, aliases, rating, status and counts are
  never taken. A display fetch that does not answer sets `MangaSeriesMetadata.DisplayFetchFailed`:
  `BookInfoProxy` then keeps the stored poster (when the pass found none) and the stored non-empty
  overview (when the pass found none), like `PosterFellBackOnMiss`. Library rule (`DisplayFallbackAllowed`): a hint found by the line's own name
  (`IsLineName`) is used as-is; one found only by alias/subtitle only when the line is in the
  entry's library (novel-type medium = light novel, anything else incl. null = manga). Debug
  `Display fallback for {name}: AniList {id} via {via} (cover|overview)`.
- **MangaDexService** — live volume count for ONGOING series (AniList's count is null while
  releasing), via `/manga` + `/manga/{id}/aggregate` (all-languages; EN-only collapses for
  licensed series). Cover fallback. Since 2026-09-16 also the **English-locale cover art per
  volume** (`GetEnglishCovers`: the series joined by `links.al == AniListId`, never by title alone;
  `/cover?locales[]=en`, cached 7 days) — the first choice for the series poster and the second for
  a volume's cover.
- **GoogleBooksService** — per-VOLUME real release date + page count + ISBN_13 (each volume is a
  published book with its own ISBN), backfilled by Open Library. Env-first `GOOGLE_BOOKS_API_KEY`.
  Since 2026-09-16 the per-volume **description** comes from the record for the volume's ISBN
  (`/volumes/{id}` — the list projection is abridged), validated by `IsAcceptableDescription`
  (English, no CJK, no product listings, ≥ 40 chars); the title search is the fallback only without
  an ISBN or a usable record; the record's largest declared cover is the third cover source; one
  retry on 429/5xx; ISBN records cached 30 days in process. No placeholder is ever written for a
  volume without a description. The keyed project's quota is 1,000 queries/day (two per volume).
- **MangaSearchService** — live indexer query → highest grabbable volume (parses release titles
  with `MangaVolumeParser`). No dependency back into the metadata layer (no DI cycle).

**Volume-count precedence:** `max(MaxVolume cap, indexer-highest, MangaDex-live, AniList-final-when-FINISHED)`,
falling back to a stub count so add always works with no indexer/metadata.

## Grabbing (the Servarr decision pipeline, adapted)

- `MangaVolumeParser` parses release titles → single `VolumeNumber` OR a pack range `VolumeStart/VolumeEnd`.
- `ParsingService.GetBooks` fans a pack range out into the matching Volume rows (Increment 4a), so one
  "Volumes 1-13" release maps to all 13 volumes — mirroring the Discography branch.
- Pack-preference ordering + chapter-fallback selection (Increments 4b/4c) are **deferred** until a
  live Prowlarr/Torznab manga indexer exists (can't be verified against mocks). See `docs/adr/0001`.
